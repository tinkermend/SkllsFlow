# Proxy Server 使用说明

## 项目简介

基于 Go + Gin 框架实现的 OpenCode 代理服务管理程序，提供启动、停止和删除 OpenCode 服务的 API 接口。

## 快速开始

### 1. 配置文件

编辑 `config/config.yaml` 配置文件：

```yaml
proxy_api_secret: c3ea4f55ad494aaf2b0a38e0c271e6ec  # API 认证密钥
server_port: 9901                                    # 服务端口
```

### 2. 启动服务

#### 方式一：使用 Makefile

```bash
make run
```

#### 方式二：直接运行

```bash
go run main.go
```

#### 方式三：使用编译后的二进制文件

```bash
./bin/proxy_server
```

服务启动后会监听配置文件中指定的端口（默认 9901）。

## API 接口说明

所有 API 接口都需要在请求头中包含 `X-Signature` 进行认证。

### 认证说明

在所有请求的 HTTP Header 中添加：

```
X-Signature: c3ea4f55ad494aaf2b0a38e0c271e6ec
```

如果认证失败，将返回：

```json
{
  "code": 401,
  "message": "认证失败: X-Signature 无效"
}
```

### 1. 启动 OpenCode 服务

**接口地址**: `POST /api/opencode_start`

**请求参数**:

```json
{
  "chat_id": "在数据库中的 chat id",
  "port": 3000,
  "auth": false,
  "auth_password": "验证密码（auth 为 true 时必填）",
  "chat_dir": "/path/to/service/directory"
}
```

**参数说明**:

- `chat_id` (string, 必填): 会话 ID
- `port` (int, 必填): 服务端口号，范围 1000-65535
- `auth` (bool, 可选): 是否需要密码认证，默认 false
- `auth_password` (string, 可选): 认证密码，当 auth 为 true 时使用
- `chat_dir` (string, 必填): 服务启动的工作目录

**响应示例**:

成功:
```json
{
  "code": 200,
  "message": "服务启动成功"
}
```

失败:
```json
{
  "code": 500,
  "message": "服务启动失败: 错误详情"
}
```

**curl 示例**:

```bash
curl -X POST http://localhost:9901/api/opencode_start \
  -H "Content-Type: application/json" \
  -H "X-Signature: c3ea4f55ad494aaf2b0a38e0c271e6ec" \
  -d '{
    "chat_id": "test123",
    "port": 4097,
    "auth": false,
    "chat_dir": "/tmp/opencode_test"
  }'
```

## 部署说明

### 1. 准备工作

确保目标服务器已安装 OpenCode 命令行工具：

```bash
# 验证 opencode 是否已安装
which opencode
opencode --version
```

### 2. 部署步骤

1. 将对应平台的可执行文件上传到服务器
2. 上传配置文件 `config/config.yaml`
3. 设置可执行权限（Unix/Linux）：

```bash
chmod +x proxy_server_linux_amd64
```

4. 启动服务：

```bash
./proxy_server_linux_amd64
```

### 3. 使用 systemd 管理服务（推荐）

创建 systemd 服务文件 `/etc/systemd/system/proxy-server.service`：

```ini
[Unit]
Description=OpenCode Proxy Server
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/path/to/proxy_server
ExecStart=/path/to/proxy_server/proxy_server_linux_amd64
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable proxy-server
sudo systemctl start proxy-server
sudo systemctl status proxy-server
```

## 常见问题

### 1. 端口被占用

如果启动服务时提示端口被占用，可以修改 `config/config.yaml` 中的 `server_port` 配置。

### 2. OpenCode 命令未找到

确保 OpenCode 已正确安装并添加到系统 PATH 环境变量中。

### 3. 权限不足

在 Unix/Linux 系统上，确保：
- 可执行文件有执行权限
- 有权限创建和删除指定的目录
- 有权限终止进程

### 4. 认证失败

检查请求头中的 `X-Signature` 值是否与配置文件中的 `proxy_api_secret` 一致。

## 注意事项

1. **安全性**:
   - 请妥善保管 `proxy_api_secret`，不要泄露给未授权人员
   - 建议在生产环境中使用 HTTPS 协议
   - 定期更换 API 密钥

2. **端口管理**:
   - 确保指定的端口未被其他服务占用
   - 端口范围必须在 1000-65535 之间
   - 建议使用高端口号（>1024）避免需要 root 权限

3. **目录管理**:
   - 确保有足够的磁盘空间
   - 定期清理不再使用的服务目录
   - 注意目录权限设置

4. **进程管理**:
   - 停止服务前确认没有正在进行的重要操作
   - 删除操作会永久删除目录，请谨慎使用
